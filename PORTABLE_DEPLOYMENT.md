# OncoAssistant: запуск с флешки и portable `.exe`

## Что важно именно для этого проекта

- Фронтенд собирается в папку `dist` командой `npm run build`.
- Сервер запускается через `start-prod.ts`, который импортирует `server.ts`.
- SQLite база создаётся как файл `patient_data.db` в текущей рабочей папке сервера.
- В production сервер отдаёт готовый фронтенд из папки `dist`.
- Порт по умолчанию: `3000`.
- Фронтенд сейчас собран с базовым путём `/app-registry/`.
- В проекте уже есть health-check: `http://127.0.0.1:3000/api/health`.

Из этого следуют два важных правила:

1. Папка `dist` должна лежать рядом с `server.ts`.
2. Файл `patient_data.db` удобнее всего хранить рядом с `server.ts` и `start-prod.ts`.

---

## Вариант 1. Запуск с флешки без прав администратора

Это самый прямой и практичный вариант для текущей структуры проекта.

### Что подготовить на вашем компьютере

1. Откройте проект.
2. Выполните:

```bash
npm ci
npm run build
```

3. Скачайте portable-версию Node.js для Windows:
   - нужна zip-версия, а не установщик
   - лучше брать LTS
   - разрядность должна совпадать с тем компьютером, где будете запускать приложение

### Как собрать флешку

На флешке создайте такую структуру:

```text
OncoAssistantPortable\
  app\
    dist\
    node_modules\
    src\
    package.json
    package-lock.json
    server.ts
    start-prod.ts
    tsconfig.json
    vite.config.ts
    .env
    patient_data.db
  node\
    node.exe
    npm.cmd
    npx.cmd
    ...
  run.bat
```

### Что куда класть

- В `app\dist\` скопируйте содержимое папки `dist` после `npm run build`.
- В `app\patient_data.db` будет храниться база пациентов.
- В `app\` положите весь рабочий проект, кроме `.git` и других лишних служебных файлов.
- В `node\` распакуйте zip-версию Node.js.

### Почему база должна лежать именно в `app\patient_data.db`

В текущем коде путь к базе задаётся так:

```ts
const dbPath = path.resolve("patient_data.db");
```

Это значит, что база создаётся в той папке, из которой запускается сервер. Поэтому для текущей структуры самый простой и стабильный вариант:

```text
OncoAssistantPortable\app\patient_data.db
```

### Почему `dist` должно лежать именно в `app\dist`

В текущем сервере production-фронтенд ищется так:

```ts
const distPath = path.resolve(__dirname, 'dist');
```

Это значит, что папка `dist` должна лежать рядом с `server.ts`.

### Файл `.env`

Создайте файл:

```text
OncoAssistantPortable\app\.env
```

Содержимое:

```env
NODE_ENV=production
PORT=3000
ALLOWED_ORIGINS=http://127.0.0.1:3000,http://localhost:3000
UI_PROTECT=true
API_AUTH_DISABLED=false
APP_PASSWORD=ПРИДУМАЙТЕ_СВОЙ_ПАРОЛЬ
DATABASE_ENCRYPTION_KEY=ПРИДУМАЙТЕ_ДЛИННЫЙ_СЕКРЕТ_МИНИМУМ_32_СИМВОЛА
```

Рекомендации:

- не оставляйте пароль `admin`
- ключ шифрования задайте один раз и потом не меняйте без необходимости
- `.env` храните только на своей флешке

### Файл `run.bat` для запуска в один клик

Создайте файл:

```text
OncoAssistantPortable\run.bat
```

Содержимое:

```bat
@echo off
setlocal
cd /d "%~dp0app"
start "OncoAssistant" "..\node\node.exe" ".\node_modules\tsx\dist\cli.mjs" ".\start-prod.ts"
timeout /t 3 /nobreak >nul
start "" http://127.0.0.1:3000/app-registry/
exit
```

### Как пользоваться на чужом компьютере

1. Вставьте флешку.
2. Откройте папку `OncoAssistantPortable`.
3. Дважды нажмите `run.bat`.
4. Подождите 3-5 секунд.
5. Откроется браузер с приложением.
6. Для проверки можно открыть:

```text
http://127.0.0.1:3000/api/health
```

Если видите JSON со статусом `ok`, значит всё запустилось правильно.

Само приложение открывайте по адресу:

```text
http://127.0.0.1:3000/app-registry/
```

Это важно, потому что в текущем проекте и Vite, и `BrowserRouter` настроены на базовый путь `/app-registry/`.

### Что важно для этого варианта

- На флешке должны быть уже установленные зависимости `node_modules`.
- Это важно из-за `better-sqlite3`: это нативный модуль, и он должен быть подготовлен заранее.
- Лучше собирать portable-папку на Windows той же архитектуры, где приложение будет запускаться.
- Если на целевом ПК очень жёсткая корпоративная политика, могут блокироваться `node.exe` или `.bat`.

### Самый безопасный практический совет

Если нужен максимально надёжный запуск без админ-прав, храните всё в одной папке:

```text
OncoAssistantPortable\app\
```

То есть:

- `dist` внутри `app`
- `.env` внутри `app`
- `patient_data.db` внутри `app`
- `server.ts` и `start-prod.ts` внутри `app`

Так меньше шансов ошибиться с путями.

## Вариант 2. Готовый portable `.exe` на вашем компьютере

Для этого проекта я рекомендую **Electron**, а не Tauri.

### Почему лучше Electron

- У вас уже есть Node/Express сервер.
- У вас уже есть SQLite через `better-sqlite3`.
- Electron проще упакует существующий backend почти без переделки архитектуры.
- Tauri здесь потребует более глубокого переноса логики на Rust-сторону или отдельной схемы запуска backend.

### Что получится в итоге

На вашем компьютере вы один раз собираете portable `.exe`, а потом переносите на флешку:

```text
OncoAssistantPortableExe\
  OncoAssistant Portable.exe
  resources\
  ...
```

Потом на чужом ПК просто запускаете `.exe`, без установки Node.js и без `npm install`.

### Общая схема сборки portable `.exe`

1. В текущем проекте делаете production-сборку:

```bash
npm ci
npm run build
```

2. Добавляете Electron-обвязку.
3. Упаковываете приложение как `portable` через `electron-builder`.
4. Копируете готовый `.exe` на флешку.

### Что нужно добавить в проект для Electron

Минимально нужны:

- `electron/main.cjs`
- `electron/preload.cjs`
- конфигурация `electron-builder`
- скрипты в `package.json`

### Логика запуска в Electron

Схема такая:

1. Electron стартует локальный backend.
2. Backend поднимает Express и SQLite.
3. Electron открывает окно на `http://127.0.0.1:3000/app-registry/`.
4. `patient_data.db` хранится рядом с приложением или в папке данных portable-сборки.

### Практически рекомендованное место для базы в `.exe` варианте

Если делаете portable `.exe`, удобнее хранить базу рядом с запускаемым файлом:

```text
patient_data.db
```

Но для этого лучше заранее поправить сервер, чтобы путь к базе брался из переменной окружения, например:

```env
DB_PATH=./patient_data.db
```

Сейчас проект этого ещё не делает автоматически, поэтому для `.exe` варианта это желательно предусмотреть в отдельном шаге упаковки.

### Самый простой рабочий процесс сборки `.exe`

На вашем компьютере:

1. Установить Electron-зависимости.
2. Собрать `dist`.
3. Упаковать проект в portable `.exe`.
4. Проверить запуск без интернета.
5. Проверить, что создаётся `patient_data.db`.
6. Проверить вход по вашему `APP_PASSWORD`.

### Когда выбирать этот вариант

Выбирайте portable `.exe`, если:

- приложение нужно запускать часто
- на чужих ПК жёсткие ограничения
- вы хотите убрать зависимость от `node.exe`
- нужен один понятный файл для запуска

## Что рекомендую лично для вашего проекта

### Если нужен результат быстро

Берите **вариант с флешкой и portable Node.js**:

- меньше переделок
- полностью совместим с текущей структурой
- легко отлаживать
- уже соответствует вашему `server.ts`

### Если нужен максимально удобный запуск

Делайте **portable `.exe` через Electron**:

- один файл для пользователя
- меньше ручных действий
- выше шанс, что приложение запустится одинаково на разных ПК

## Короткая инструкция без лишнего

### Быстрый вариант с флешки

1. На своём ПК выполните:

```bash
npm ci
npm run build
```

2. Скопируйте на флешку:
   - весь проект
   - папку `dist`
   - папку `node_modules`
   - portable Node.js
   - файл `.env`
   - файл `run.bat`

3. Храните базу здесь:

```text
app\patient_data.db
```

4. Запускайте двойным кликом по `run.bat`.

### Быстрый вариант с `.exe`

1. На своём ПК соберите production-версию.
2. Оберните проект в Electron.
3. Соберите portable `.exe`.
4. Скопируйте готовый `.exe` на флешку.
5. Запускайте на чужом ПК без установки Node.js.

---

## Что проверить после подготовки

- Открывается `http://127.0.0.1:3000/app-registry/`
- Отвечает `http://127.0.0.1:3000/api/health`
- Логин работает с вашим паролем
- После создания пациента появляется или обновляется `patient_data.db`
- После перезапуска данные не пропадают

## Вывод

Для текущего состояния проекта самый практичный вариант без админ-прав:

1. собрать проект у себя
2. положить `dist` в `app\dist`
3. хранить базу в `app\patient_data.db`
4. запускать через portable Node.js и `run.bat`

Если нужен самый удобный формат для конечного пользователя, следующий шаг — portable `.exe` через Electron.
